## [PyPI Blocks File Uploads to Releases Older Than 14 Days](https://simonwillison.net/2026/Jul/23/seth-larson/#atom-everything) ⭐️ 8.0/10

The Python Package Index (PyPI) now rejects new file uploads to releases that are older than 14 days. This restriction was implemented by Seth Larson to prevent supply chain poisoning if publishing tokens or workflows are compromised. This change significantly enhances the security of the Python ecosystem by mitigating the risk of attackers retroactively injecting malicious code into long-stable packages. It protects downstream users and dependent systems from supply chain attacks that exploit outdated but trusted release artifacts. The policy applies specifically to preventing the poisoning of old and long-stable releases in case of credential theft. As of the announcement, there is no evidence that this attack vector has been actively abused, suggesting it is a proactive defense measure.

rss · Simon Willison · Jul 23, 04:50

**Background**: Supply chain attacks involve injecting malicious code into software packages to compromise dependent systems, often targeting trusted vendors to steal data or deploy ransomware. PyPI relies on API tokens for package publishing, and if these tokens or CI/CD workflows are compromised, attackers could potentially modify existing releases. By restricting uploads to recent versions only, PyPI limits the window of opportunity for such retroactive tampering.
