## [Fil-C 实现上下文切换 API 的内存安全](https://fil-c.org/context_switches) ⭐️ 8.0/10

Fil-C 实现了具有内存安全的 setjmp/longjmp 和 ucontext API，解决了关键的栈帧验证和寄存器状态完整性问题。此更新确保上下文切换不会导致传统 C 编程中常见的未定义行为或内存损坏。 这一进展通过消除主要的安全漏洞来源，显著提高了 C 和 C++ 底层系统编程的可靠性。它允许开发人员在不牺牲内存安全保证的情况下，安全地使用这些 API 来实现纤维（fibers）和协程。 该实现涉及严格的栈帧验证和编译器强制执行的控制流完整性，以防止无效的上下文恢复。与标准 C 库不同，Fil-C 在运行时捕获内存安全错误，确保 longjmp 仅执行到有效且活动的栈帧。

hackernews · modeless · 6月30日 00:38 · [社区讨论](https://news.ycombinator.com/item?id=48727177)

这篇文章反对将 AI 智能体视为人类同事，主张在自主智能体和被动助手之间做出更清晰的区分，以防止有害的拟人化倾向。 这一观点具有重要意义，因为它解决了将人类特质过度归因于 AI 所带来的心理和组织风险，这可能导致在职场动态中产生错误的信任和不可现实的期望。 文章强调了管理项目的“智能体”与提供信息的“助手”之间的语义差异，并警告称给 AI 工具命名（如“亚历克斯”）会模糊这些功能界限。

rss · MIT Technology Review · 6月29日 18:00

**背景**: 拟人化是指将类似人类的感情、心理状态和行为归因于非人类实体，包括人工智能系统。在人工智能的背景下，这通常涉及给工具起人类名字或将它们视为同事，这会影响用户的行为和信任水平。区分被动的 AI 助手和自主的 AI 智能体对于理解它们的实际能力和局限性至关重要。
