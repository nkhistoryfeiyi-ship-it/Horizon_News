## [Arbitrary code execution in QubesOS via copy-to-VM error reporting backchannel](https://www.qubes-os.org/news/2026/08/29/qsb-118/) ⭐️ 7.0/10

QubesOS disclosed QSB-118, a critical arbitrary code execution vulnerability in the copy-to-VM error reporting backchannel that affects Dom0-originating operations. The vulnerability exists in the Dom0 variant of qvm-copy-to-vm, which uses system() for error reporting, while the VM variant is not affected. This is significant because QubesOS is specifically designed as a security-focused operating system using Xen virtualization, making any arbitrary code execution in Dom0 particularly concerning. Dom0 is the privileged domain that controls all other VMs, so a compromise here could undermine the entire security model. The vulnerability only affects the Dom0 variant of qvm-copy-to-vm, which uses system() for error reporting. The VM variant is not affected because its version of the error reporting function does not use system(). This is a classic command injection vulnerability where user-controlled input could be passed to system().

hackernews · vntok · Aug 30, 08:51 · [Discussion](https://news.ycombinator.com/item?id=49496918)

**Background**: QubesOS is a security-focused Linux distribution that uses Xen hypervisor to isolate applications into separate virtual machines. Dom0 is the privileged domain that manages all other VMs and has direct hardware access. The copy-to-VM functionality allows users to transfer files between VMs through Dom0, which acts as an intermediary. This architecture is designed to minimize the attack surface by ensuring that even if one VM is compromised, the attacker cannot easily escalate to Dom0 or other VMs.
